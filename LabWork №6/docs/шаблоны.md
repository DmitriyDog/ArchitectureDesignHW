## 1. Порождающие шаблоны
### 1.1. Singleton (Одиночка) - класс DatabaseConnection  
Общее назначение: Гарантирует, что класс имеет только один экземпляр,
и предоставляет глобальную точку доступа к этому экземпляру.  
Назначение в проекте: В системе управления рестораном должно быть
только одно подключение к базе данных, чтобы избежать конфликтов при одновременных запросах и избыточного расходования ресурсов.  
```py
class DatabaseConnection:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super().__new__(cls)
                    cls._instance.connection_string = "postgresql://localhost:5432/restaurant"
                    print(f"Создание подключения к БД: {cls._instance.connection_string}")
        return cls._instance
```

### 1.2. Фабричный метод - иерархия DishFactory и Dish
Общее назначение: Определяет интерфейс для создания объекта, но позволяет подклассам изменять тип создаваемых объектов.  
Назначение в проекте: Ресторан имеет разные типы блюд (пицца, паста, салат),
каждое из которых требует своего способа приготовления. Фабричный метод позволяет создавать конкретные блюда, не привязываясь к их классам.  
```py
class DishFactory(ABC):
    @abstractmethod
    def create_dish(self) -> Dish:
        pass
    
    def order_dish(self) -> Dish:
        dish = self.create_dish()
        dish.prepare()
        dish.serve()
        return dish

class PizzaFactory(DishFactory):
    def create_dish(self) -> Dish:
        return Pizza()
```

### 1.3. Builder (Строитель) - класс Order с внутренним OrderBuilder
Общее назначение: Позволяет создавать сложные объекты пошагово, разделяя конструирование и представление объекта.  
Назначение в проекте: Заказ в ресторане может содержать множество параметров:
список блюд, адрес доставки, особые пожелания и т.д. Строитель позволяет создавать заказ поэтапно, делая код читаемым и гибким.  
```py
class Order:
    def __init__(self, builder):
        self.dishes = builder.dishes
        self.customer_name = builder.customer_name
        
    class OrderBuilder:
        def __init__(self, customer_name: str):
            self.customer_name = customer_name
            self.dishes = []
        
        def add_dish(self, dish: Dish):
            self.dishes.append(dish)
            return self
        
        def build(self):
            return Order(self)
```

## 2. Структурные шаблоны
### 2.1. Adapter (Адаптер) - класс ExternalPaymentAdapter
Общее назначение: Преобразует интерфейс одного класса в другой интерфейс, ожидаемый клиентом.  
Назначение в проекте: Ресторан использует внутреннюю систему оплаты, 
но нужно интегрироваться с внешним платежным шлюзом. Адаптер позволяет использовать внешний шлюз через единый интерфейс платежной системы.  
```py
class PaymentProcessor(ABC):
    @abstractmethod
    def process_payment(self, amount: float):
        pass

class ExternalPaymentAdapter(PaymentProcessor):
    def __init__(self, external_gateway: ExternalPaymentGateway):
        self.external_gateway = external_gateway
    
    def process_payment(self, amount: float):
        self.external_gateway.send_payment_request(amount, "RUB")
```

### 2.2. Decorator (Декоратор) - иерархия DishDecorator
Общее назначение: Динамически добавляет новые обязанности объекту, являясь гибкой альтернативой наследованию.  
Назначение в проекте: В ресторане можно добавлять дополнительные ингредиенты к блюдам (сыр, бекон).
Декоратор позволяет динамически расширять функциональность блюда без изменения его класса.  
```py
class DishDecorator(MenuItem):
    def __init__(self, decorated_dish: MenuItem):
        self.decorated_dish = decorated_dish

class ExtraCheese(DishDecorator):
    def get_description(self) -> str:
        return f"{self.decorated_dish.get_description()} + сыр"
    
    def get_price(self) -> float:
        return self.decorated_dish.get_price() + 50.0
```

### 2.3. Facade (Фасад) - класс KitchenFacade
Общее назначение: Предоставляет унифицированный интерфейс к набору интерфейсов подсистемы, упрощая её использование.  
Назначение в проекте: Кухня ресторана имеет сложную структуру с разными фабриками для разных типов блюд.
Фасад предоставляет простой интерфейс для приготовления комплексных обедов.  
```py
class KitchenFacade:
    def __init__(self):
        self.pizza_factory = PizzaFactory()
        self.pasta_factory = PastaFactory()
        self.salad_factory = SaladFactory()
        self.prepared_dishes = []
    
    def prepare_full_meal(self):
        print("=== Приготовление комплексного обеда ===")
        self.prepared_dishes.append(self.pizza_factory.create_dish())
        self.prepared_dishes.append(self.pasta_factory.create_dish())
        self.prepared_dishes.append(self.salad_factory.create_dish())
```

### 2.4. Composite (Компоновщик) - иерархия MenuComponent
Общее назначение: Компонует объекты в древовидные структуры для представления иерархий "часть-целое",
позволяя клиентам единообразно работать с отдельными объектами и их группами.  
Назначение в проекте: Меню ресторана содержит отдельные блюда и комбо-наборы.
Компоновщик позволяет одинаково работать как с отдельными блюдами, так и с комбо.  
```py
class MenuComposite(MenuComponent):
    def __init__(self, name: str):
        self.name = name
        self.components = []
    
    def add_component(self, component: MenuComponent):
        self.components.append(component)
    
    def get_price(self) -> float:
        return sum(component.get_price() for component in self.components)
```

## Поведенческие шаблоны
### 3.1. Observer (Наблюдатель) - классы OrderSubject, Customer, KitchenStaff
Общее назначение: Создает механизм подписки, позволяющий одним объектам следить и реагировать на события, происходящие в других объектах.  
Назначение в проекте: Клиенты и персонал кухни должны получать уведомления об изменении статуса заказа.
Наблюдатель позволяет автоматически оповещать всех заинтересованных лиц.  
```py
class OrderSubject:
    def attach(self, observer: OrderObserver):
        self._observers.append(observer)
    
    @order_status.setter
    def order_status(self, status: str):
        self._order_status = status
        self._notify_observers()
```

### 3.2. Strategy (Стратегия) - иерархия PricingStrategy
Общее назначение: Определяет семейство алгоритмов, инкапсулирует каждый из них и обеспечивает их взаимозаменяемость.  
Назначение в проекте: В ресторане могут применяться разные стратегии расчета стоимости:
обычная цена, скидка для новых клиентов, скидка постоянным клиентам. Стратегия позволяет легко менять алгоритм расчета.  
```py
class PricingStrategy(ABC):
    @abstractmethod
    def calculate_price(self, base_price: float) -> float:
        pass

class DiscountPricing(PricingStrategy):
    def __init__(self, discount_percent: float):
        self.discount_percent = discount_percent
    
    def calculate_price(self, base_price: float) -> float:
        return base_price * (1 - self.discount_percent / 100)
```

### 3.3. Command (Команда) - классы KitchenCommand, PrepareDishCommand, Chef
Общее назначение: Превращает запросы в объекты, позволяя передавать их как аргументы при вызове методов, ставить в очередь, логировать, а также поддерживать отмену операций.  
Назначение в проекте: Запросы к повару на приготовление блюд нужно ставить в очередь и иметь возможность отмены. Команда инкапсулирует эти запросы в объекты.  
```py
class KitchenCommand(ABC):
    @abstractmethod
    def execute(self):
        pass
    
    @abstractmethod
    def undo(self):
        pass

class PrepareDishCommand(KitchenCommand):
    def execute(self):
        self.chef.cook_dish(self.dish_name)
```

### 3.4. Chain of Responsibility (Цепочка обязанностей) - иерархия OrderHandler
Общее назначение: Позволяет передавать запросы последовательно по цепочке обработчиков, пока один из них не обработает запрос.  
Назначение в проекте: Заказ проходит несколько этапов: валидация, приготовление, доставка. Каждый этап обрабатывается своим обработчиком.  
```py
class OrderHandler(ABC):
    def set_next(self, handler):
        self._next_handler = handler
        return handler
    
    def handle(self, order: Order):
        if self._next_handler:
            self._next_handler.handle(order)
```

### 3.5. State (Состояние) - иерархия OrderState и класс OrderContext
Общее назначение: Позволяет объекту изменять свое поведение в зависимости от внутреннего состояния, создавая впечатление, что объект меняет свой класс.  
Назначение в проекте: Заказ может находиться в разных состояниях: новый, готовится, готов, доставлен. Поведение методов зависит от текущего состояния.  
```py
class OrderState(ABC):
    @abstractmethod
    def next(self, context):
        pass

class OrderContext:
    def next_state(self):
        self._state.next(self)
```
